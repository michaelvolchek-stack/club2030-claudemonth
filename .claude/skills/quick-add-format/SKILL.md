# Quick Add — פורמט NLP עברי

הפרסר: `src/lib/actions/quickAdd.ts` → `parseQuickAdd(text)` מחזיר `QuickAddResult`
(`title, dueDate, dueHasTime, plannedDate, priority, projectName, tagNames`).

## מבנה
```
"כותרת [תאריך] [!עדיפות] [#פרויקט] [@תגית...] [~תכנון]"
```

## טוקנים

| Token | משמעות | הערה |
|-------|--------|------|
| `!1`–`!4` | עדיפות | 1=דחוף, 2=גבוה, 3=בינוני (ברירת מחדל), 4=נמוך |
| `#name` | פרויקט (יחיד) | מקבל עברית/לטינית/ספרות/`_`/`-` |
| `@name` | תגית (מרובות) | נאספות בלולאה גלובלית |
| `~expr` | תאריך **תכנון** | מריץ את פרסר התאריך על הטוקן שאחרי `~` בלבד |
| תאריך יעד | ראה טבלת התאריכים | מזוהה מהטקסט שנותר |

## תאריכי יעד (סדר הזיהוי ב-`parseDateFromText` — חשוב!)
הפרסר מנסה לפי הסדר, ועוצר בהתאמה הראשונה:
1. `בעוד [N] ימים/שבועות/חודשים` (גם בלי N → 1). יחידה לפי אות ראשונה: י/ש/ח.
2. `ב-DD/MM` או `ב-DD.MM` — אם עבר, מקדם לשנה הבאה.
3. `ב-DD ב<חודש>` (שמות חודשים עבריים) — אם עבר, שנה הבאה.
4. `ב-DD` (יום בחודש הנוכחי/הבא) — אם עבר או היום, מקדם לחודש הבא.
5. `ביום [ה]<יום>` — היום הבא בשבוע (`nextDayOfWeek`, תמיד קדימה).
6. מילות מפתח: `היום` / `מחרתיים` / `מחר` / `השבוע`.

## שעות (מתווספות אחרי/בלי תאריך, מדליקות `dueHasTime`)
- `בבוקר`→09:00 · `בצהריים`→13:00 · `בערב`→19:00 · `בלילה`→22:00
- `HH:MM` — שעה מפורשת.

## דוגמאות
```
"לפגוש יעל מחר בבוקר !1 #עבודה @פגישות"
"לשלם חשבון !2 ב-5 ביוני"
"לכתוב דוח בעוד שבוע #עבודה ~מחר"
```

## אילוצים שיש לשמר בכל שינוי
- כל טוקן שמזוהה **מוסר** מ-`remaining`; מה שנשאר (מנוקה מרווחים) הוא ה-`title`. אם ריק → `title = text` המקורי.
- `#`/`@` תומכים בטווח היוניקוד `֐-׿` (עברית) + `a-zA-Z0-9_-`.
- `~` מפעיל את **אותו** `parseDateFromText` אבל על טוקן בודד → אל תשבור את ההפרדה בין `plannedDate` (מתי לטפל) ל-`dueDate` (יעד).
- שמירה על סדר הזיהוי מונעת התנגשויות (למשל `ב-15/6` לא ייתפס בטעות ע"י כלל `ב-DD`).
